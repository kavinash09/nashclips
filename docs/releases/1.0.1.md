# nashclip 1.0.1

This source release adds versioned GitHub distribution for the existing native
Swift clipboard app. The Homebrew formula builds it locally using Apple's
Command Line Tools. No paid Apple Developer membership is needed for this route.

## Install or upgrade

With Homebrew and compatible Apple Command Line Tools installed:

```sh
brew tap kavinash09/nashclip https://github.com/kavinash09/nashclips.git
brew install --formula kavinash09/nashclip/nashclip
nashclip
```

Existing users: quit nashclip, run `brew update`, then
`brew upgrade --formula kavinash09/nashclip/nashclip`.

If the development tools are missing, first run `xcode-select --install` and
finish installation. The app's deployment target is macOS 13; Homebrew and the
compiler have their own supported OS requirements. Apple Silicon is the only
locally validated architecture. Java implementations remain available as source.

## Downloads

- `nashclip-1.0.1-source.tar.gz`: source from tag `v1.0.1`, including LICENSE and NOTICE.
- `SHA256SUMS`: exact checksum of that uploaded source archive.

These are source files, not a prebuilt `.app`. Alternatively, extract the source
and run `sh nashclip-swift/run.sh` from its root. The Swift app reports version
1.0.1, build 2. No app feature or paste implementation changed in this release.

## Privacy and limitations

Quit other nashclip variants before launching. Enable nashclip in System
Settings → Privacy & Security → Accessibility for automatic paste. Locally
signed app updates may require renewing that permission. Swift successful
external-app paste has not been verified after the earlier permission diagnosis;
Use still supports clipboard copy and manual paste fallback.

History is readable local text in `~/.nashclip`. Pause or quit before copying
secrets. Homebrew uninstall preserves history and settings. There is no sync,
encryption, search, image history, expiration, or automatic launch at login.

This is not a production-certified binary release. Developer ID signing,
notarization, clean-machine/Intel validation, broad native UI acceptance,
responsiveness, and sustained resource profiling remain pending. See the
repository's release verdict and project memory for scope and dated evidence.
